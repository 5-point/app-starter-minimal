# Frozen API client

This folder is a **vendored, generated snapshot** of the ERP API client.
Treat it as build output, not source code.

## What it is

- **Generator:** [orval](https://orval.dev/) (typed client, TanStack Query
  hooks, URL getters, Zod schemas)
- **API baseline:** teamspace API, OpenAPI spec `2026.3.27`
- **Layout:** `generated/` (typed client, query hooks, URL getters),
  `zod/` (Zod schemas), `mutator/custom-instance.ts` (the single
  hand-written integration point: base URL, auth headers, response
  normalization — re-exported by `index.ts`)
- **No mock files:** the client is generated with `mock: false`
  (mock mode in the app templates is implemented with hand-written MSW
  handlers), so there are no `.msw.ts`/`.faker.ts` files to strip on re-copy

## Rules

- **Never edit anything in this folder** (including `mutator/`), and never
  add regeneration tooling — this template has no orval.
- Import only via the barrel `@/lib/api-client` (or
  `@/lib/api-client/zod` for schemas).
- Guard the URL getters you rely on in `src/api/generated-urls.test.ts`:
  a newer snapshot can rename duplicate operationIds and silently repoint
  calls to different endpoints.

## Maintenance (how this folder is produced)

This section describes how the 5 POINT team maintains the snapshot inside
the template's source project — as a template user you never need to do
this; updates ship with new template releases.

1. The snapshot is generated by [orval](https://orval.dev/) from a
   teamspace/projectfacts OpenAPI baseline (the client is generated with
   `mock: false`, so there are no `.msw.ts`/`.faker.ts` files).
2. Typecheck and build verify the snapshot; fallout is fixed in app code,
   never in the snapshot.
3. Generated functions keep stable path-derived resource names (e.g.
   `getPdfInvoice`), so the calls the app makes only shift when upstream
   changes the path itself.
4. The "API baseline" line above records the spec version of the snapshot.
